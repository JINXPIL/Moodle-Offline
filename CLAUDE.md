# Moodle Offline

Локальное приложение (Python + веб-интерфейс на localhost, собирается в .exe через PyInstaller) для студента СевГУ:
скачивает материалы курсов Moodle (https://do.sevsu.ru), сохраняет расписание (schedule.sevsu.ru, timetable.sevsu.ru)
и записывает на элективы по физкультуре (iot.sevsu.ru). Должно работать и онлайн, и офлайн, в том числе когда Moodle недоступен.

## Файлы
- `moodle_offline.py` — ядро: вход, клиент Moodle, загрузка, докачка, ZIP-бэкап, консольная версия, `VERSION`.
- Страница курса → `parse_sections`/`parse_activity` в `moodle_offline.py`: помимо файлов читает отметку выполнения (`Item.done`: `completion_state` по значку `completion-(auto|manual)-(y|pass|n|fail)` из `.actions`, Moodle 3.x; для 4.x разметка не проверялась) и ограничения доступа (`Item.restriction`/`Section.restriction`: `.availabilityinfo` без плашки «Ограничено»); пишется в `.course.json`, `README.md`, `index.html` курса и в окно курса (`doneSummary`/`DONE_UI` в `ui/index.html`). «Посещаемость» (`mod_attendance`): обработчик `Processor.h_attendance` открывает `…&view=5` («Все» — по умолчанию сайт показывает месяц), `parse_attendance` (занятия, статусы → `attendance_kind`, итог `table.attlist`) → `Item.attendance` (в `.course.json`, README/index курса, `attHtml` в `ui/index.html`), страницу чистит `attendance_fragment` (вкладки `ul.nav-tabs` и `.attfiltercontrols` убираются); элемент в `RECHECK_IN_SYNC`. Оценки: `grades_sync` — один запрос `/grade/report/overview/index.php` после загрузки (`JobOptions.grades_on`, настройка `save_grades`, `--no-grades`) → `.moodle_grades.json` (`GRADES_FILE`, `load_grades`; в `transfer.py` едет с категорией «курсы»), `parse_grades_overview` (`table#overview-grade`, id курса из ссылки `course/user.php?mode=grade&id=`); `gui.py` `course_list` добавляет `grade`. Посещаемость и сводка оценок сверены с настоящими страницами, отчёт `grade/report/user` внутри курса и Moodle 4.x — нет. Разметка сверена с настоящей страницей курса do.sevsu.ru (14 разделов, 43 элемента, 20 отметок) — но сами присланные страницы в репозиторий не кладём (имя, `sesskey`).
- `ui/index.html`, телефон (`@media (max-width:700px)`): «Загрузки» — не плашка внизу, а значок `#dlBtn` в шапке (процент пока идёт, `data-st` красит по состоянию, точка `.mark` по `dlKey` — не просмотренный итог; `renderDlBtn`, `showDock`/`openDock`/`closeDock`) + полоска `#topProg` под шапкой; `.dock` на телефоне — `position:fixed` лист на весь экран (z-index 48, ниже окон `.modal` = 50), `#dockClose`, панель `.now` с «Пауза/Стоп» видна (в `@media 980` она скрыта — там переопределено `.dock .now`), `.now.idle` прячет её, когда делать нечего; `moBack` закрывает лист. Плашки `.banner` (`renderNet`: офлайн, сессия, VPN; разметка `.bn-t`>`b`+`.bn-d`, кнопки `.bn-keep`/`.bn-btns`) на телефоне — одна строка: заголовок ≤2 строк + «Войти», по нажатию на `.bn-t` `.open` раскрывает пояснение и кнопки (делегированный обработчик на `#bannerWrap`, `setBarVars()` после переключения); `.updbar` без подписи `.s`; `.schhead` 40px, область расписания «−52px». Расписание: `body.sched-lock` (страница не прокручивается), высота `#schFrame` = экран − `--top-h` − `--above-h` − `--bnav-h` (их считает `setBarVars`, `--bnav-h` — реальная высота нижних вкладок) − 60px (строка выбора), настройки (`#scheduleView .side`) — лист `.side-open` на весь экран (`schSide`). Внутри просмотрщика (`schedule.py`): `html:not(.wide) .bar{top:-52px}` (верхняя строка уезжает при прокрутке, в низком окне `-46px`), фильтры — нижний лист `.fpanel.open` + `#fscrim` (`fToggle`). Проверено в Chromium на 320–412 px, на настоящем Android WebView — нет.
- `gui.py` + `ui/index.html` — локальный веб-интерфейс и его API (файлы из папки материалов отдаются по `/f/<ключ>/<путь>` — ключ в адресе, чтобы у открытой страницы грузились её относительные скрипты и стили; поддерживается Range; «Загрузки»: общий процент/скорость и список по курсам из `GuiReporter.overall/plan`); офлайн-режим, сохранённый вход (шифрование DPAPI на Windows). Курсы, лежащие в папке сохранения (`.course.json`), но не записанные в `.moodle_state.json` (после «Переноса данных» состояние не переносится), `App.adopt_courses` → `moodle_offline.adopt_courses` дописывает в состояние: в итоге переноса, при открытии списка курсов и окна курса, в офлайн-режиме; не во время загрузки — иначе окно курса считало бы их «не скачано».
- `schedule.py` — расписание: официальный JSON-API schedule.sevsu.ru, личное timetable.sevsu.ru, просмотрщик (HTML со встроенными данными; адаптивный: `html.wide` — компьютер/планшет, иначе телефон; виды день/неделя/месяц/список, свайп, размер текста; размеры в `rem`, цвета типов — `--kc`).
- `sch_book.py` — чужие расписания: профили в `Расписание/Другие группы/<код>/` (`.profile.json`: название, `auto`, источники, `excel`, `origin` site/file, `last_used`), `list_profiles` (своё первым, дальше по `last_used`), `auto_profiles` (обновляются в `extra_sync` → `other_schedules_sync`, по умолчанию выключено; при `NetworkDown` цикл прерывается), `export_zip` → `Расписание/Поделиться/*.zip` (формат `moodle-offline-schedule` v1: `manifest.json`, `README.txt`, на каждое расписание `schedule.json` + `index.html` + `.ics`; без личных данных, снимков и настроек), `import_zip` (читает только ожидаемые имена, код группы по `^[a-z0-9][a-z0-9\-]{0,59}$`, уроки проходят `_clean_lessons`, страница пересобирается сама — чужой HTML не берётся; источник `imported` в `schedule.py` не перекрывает даты, на которые ответил сайт); `pick_title` берёт название с сайта только если код совпал. API — `gui.py` `/api/schedule/other/*`, `/api/schedule/share`, `/api/schedule/import` (тело — сырой zip), `/api/schedule/profile/use`; `_schedule_job_other` — только schedule/excel, без входа; консоль `--schedule … --group … --other`; окно — выбор в `#schSelD`/`#schSelM` + панель `#schBook` в `ui/index.html` (свои панели помечены `.own-only`, скрываются у чужого); Android — `android.share_file` ↔ `Bridge.shareFile` (FileProvider `.files`, `termux-share`); `transfer.py` не переносит `Поделиться/`. Просмотрщик у каждого расписания хранит настройки отдельно (пространство имён в localStorage). Без Moodle-кода и сторонних библиотек.
- `xlsx_schedule.py` — Excel-расписание СевГУ (https://www.sevsu.ru/univers/shedule/): свой читатель xlsx (zip + XML, без сторонних библиотек), блоки групп по 10 столбцов на листах «уч.н. N», подгруппы, многострочные ячейки потоков, адрес корпуса по листу «Справка»; в `schedule.py` — источник `excel` (`find_excel_links`, `rank_excel`, `match_sig`, `ScheduleJob._run_excel`; в `load_merged` Excel не добавляет пары на даты, за которые уже отвечали другие источники — поле `covered`); только https `*.sevsu.ru`; страницу сайта без входа я не видел — разбор ссылок проверен на макетах (аккордеон, таблица, плоский список).
- `iotapi.py` — элективы через API iot.sevsu.ru (SPA на Vue, REST `/api`, ключ доступа из Keycloak `auth.sevsu.ru`, область `portal`, клиент `iot`, вход по коду + PKCE вручную без браузера): блоки, варианты и места, выбор «основной + резервы» (правило как `canBeSaved` на сайте), занятия и запись, `Элективы/iot.json`, `diff_states` для уведомлений; пароль только на https `*.sevsu.ru`, ключ только в памяти; ходит через `MoodleClient` (паузы, повторы). Выбор и запись — только по нажатию. Не проверялся на настоящем сайте (вход закрыт): проверка на макете `mock_iot.py`.
- `electives.py` — запасной способ для элективов: страница iot.sevsu.ru в фоновом браузере (`cdp.py`), поиск кнопок записи; на Android недоступен.
- `reader.py` — «читалка» элементов курса: `render` чистит HTML страницы Moodle до безопасного вида (разрешённые теги, ссылки помечены `data-rgo/rfile/rext`, картинки `data-src`; формы, скрипты, `sesskey`-ссылки и ссылки-действия убираются), кэш страниц/картинок в `.moodle_offline/reader`; без сети и Moodle-кода (страницу даёт `MoodleClient.fetch_internal`, API — `gui.py`: `/api/reader`, `/api/reader/file`; только адреса своего Moodle; html/svg — только скачиванием).
- `reserve.py` — резерв файлов (раздел 4е README): если файл на сайте заменили (новый адрес, то же место на диске), `Processor._on_replace` (хук `MoodleClient.download(before_replace=…)`, срабатывает после полной загрузки, до замены) убирает прежнюю версию в `<Курс>/_Резерв/…` (имя «… (заменён ГГГГ-ММ-ДД чч-мм)», список `.versions.json`, хранится 3 версии), признак «заглушка» (`stub_reason`: новый ≥5× меньше, от 20 КБ, или пустой), событие `file_replaced` в «Что нового» (`news.make_event(old_path=…)`); настройка `keep_versions` (по умолчанию включена, `--no-reserve`), в окне курса — `course_structure` отдаёт `reserve`; без Moodle-кода и сторонних библиотек. Одинаковое содержимое (sha1) не архивируется; заменённое на другое место не отслеживается. При включённом резерве быстрая синхронизация перепроверяет ресурсы не чаще `RESOURCE_RECHECK` (сутки) — иначе замену не увидеть при автообновлении.
- `news.py` — «Что нового»: сравнение курса с прошлым разом, лента `.moodle_news.json`, текст и отправка уведомлений (Windows, Telegram, webhook); без Moodle-кода, страницы ему отдаёт `moodle_offline.py` (`Processor.news_pass`).
- `search.py` — «Поиск по материалам»: офлайн-индекс (SQLite FTS5) в `.moodle_search.sqlite` в папке с материалами, чтение PDF/Office/ODF/HTML/текста, разбор запроса; без Moodle-кода, сторонние библиотеки только для PDF — `pypdfium2` (быстрая) и запасная чисто-питоновская `pypdf` (Android); индексацию запускают `moodle_offline.py` (`search_pass`) и `gui.py`.
- `deadlines.py` — «Календарь и дедлайны»: сроки из календаря Moodle (`core_calendar_*` через `MoodleClient.ajax`), хранилище `.moodle_deadlines.json`, напоминания (виды новостей `deadline_*`), повестка вместе с парами, `Календарь/moodle_calendar.ics` и офлайн-страница; без Moodle-кода и без сторонних библиотек, запросы делает `moodle_offline.py` (`calendar_sync`, `calendar_watch`).
- `watch.py` — таймер «жив ли Moodle» и автообновление: настройки (`settings["watch"]`), дни/часы, `Tracker` (упал/ожил → виды новостей `moodle_down`/`moodle_up`), `auto_due`, замок `watch.lock`, состояние `watch.json`, автозапуск Windows (VBS в папке автозагрузки); без сети и сторонних библиотек, запросы делают `gui.py` (пока открыто окно) и `moodle_offline.py --watch` (`cli_watch`, `auto_update`, `audit_downloads`).
- `updater.py` — обновление самой программы: версии (`parse_version`/`is_newer`), один запрос «последний релиз» к `api.github.com` (только requests; ничего личного), настройки `settings["update"]` (`auto` по умолчанию включён, `every`, `skip`, `notified`, кэш `latest`), `due`, `status`, `should_notify`, ссылки только `github.com/JINXPIL/Moodle-Offline/`, подсказка по платформе (exe / apk / Termux / исходники). Только у exe (по кнопке «Обновить сейчас», `gui.py` `update_install_start`/`update_restart`, API `/api/update/install|restart`, `can_install` в `/api/update`): `download_verified` (https GitHub, перенаправления только `github.com`/`*.githubusercontent.com`, SHA-256 из ассета `MoodleOffline.exe.sha256`, размер, «MZ», `.part` → `.new`), `swap_exe` (запущенный exe переименовывается в `.old`, новый встаёт на место, откат при сбое), `launch` (`PYINSTALLER_RESET_ENVIRONMENT=1`), `cleanup` при старте. Без `.sha256` в релизе или без права писать рядом с exe кнопки нет (ручной путь). Одна копия: `gui_main` через `running_instance` (`gui.json` + `/api/ping` с `version`/`pid`) — работает старая версия → `hand_off` (`/api/quit` с `why=replaced`, ждёт до 75 с) и запуск новой; та же/новее → только открыть окно. Закрывающаяся копия выставляет `App.closing` (`update` — после «Перезапустить и обновить», живёт до прихода новой или 25 с; `replaced` — по просьбе новой, сервер уходит через `CLOSE_GRACE`), `/api/state` отдаёт `closing`, а `poll()` в `ui/index.html` по нему (или по потере связи после него) вызывает `closeSelf()` → `window.close()` (в окне `--app` с одной записью истории работает; во вкладке — остаётся подпись); `updater.cleanup_later` убирает `.old`/`.new` с повторами в фоне. Для окон версий до 1.17.1 (их JS закрыться не умеет): `hand_off` после ухода прежней копии зовёт `gui.close_old_windows` — Windows, ctypes, `WM_CLOSE` окнам класса `Chrome_WidgetWin_1` с заголовком ровно «Moodle Offline» (`_WinApi`; тест — подставной список окон); на Windows не проверялось. Окно — панель «Обновление программы» и плашка `#updBar` в `ui/index.html`, таймер в цикле `gui.py` и `update_tick` в `moodle_offline.py --watch`; без Moodle-кода.
- `android.py` — Android (Termux): `is_android`, открытие файлов/ссылок, уведомления `termux-notification`, `termux-wake-lock`, автозапуск Termux:Boot, папка материалов в общей памяти; окно — браузер телефона, сервер на 127.0.0.1; пароль на Android не сохраняется (нет DPAPI); без сторонних библиотек; `install_termux.sh` ставит всё в Termux.
- `apk_main.py` + `android-app/` — приложение `.apk`: Gradle-проект (Java, Chaquopy 17; четыре варианта `productFlavors` по процессору: `arm64` — Python 3.13 / arm64-v8a, `arm32` — Python 3.11 / armeabi-v7a, `x64` — Python 3.13 / x86_64, `universal` — Python 3.11 / все четыре; 32-битные процессоры в Chaquopy только с Python ≤ 3.11, в одном apk одна версия Python; код должен работать и на 3.11, и на 3.13 — не использовать то, чего нет в 3.11; в Releases универсальный — `MoodleOffline.apk`, остальные `MoodleOffline-<abi>.apk`, подпись и versionCode у всех одинаковые, `smoke.sh` ставит `x64` и `universal`, `EXPECT_PY` проверяет версию Python), окно — WebView с тем же `ui/index.html`, служба переднего плана держит сервер `gui.py` и таймер, мост `Bridge.java` ↔ `android.py` (открыть папку в «Файлах»: `Bridge.openFolder`/`canOpenFolder` — intent VIEW/BROWSE `vnd.android.document/directory` на `content://com.android.externalstorage.documents/…`, только папки в общей памяти, в `<queries>` манифеста; `gui.open_path` на Android для папок и «Показать в папке» → `android.open_folder`, для внутренней памяти — подсказка «Положить в Документы»; окно: `androidOpen` в `ui/index.html` для .apk ходит на сервер; самопроверка `apk_main._selftest` пункт `folder`; на настоящих телефонах не проверялось) (системное «Назад»: `MainActivity.onBackPressed` → JS `window.moBack()` из `ui/index.html` закрывает верхнее окно или курс, иначе сворачивает приложение) (флаг `MOODLE_OFFLINE_APK=1`; уведомления, файлы, wake lock, автозапуск, доступ к «Документам»). Python-файлы и `ui/` копируются в приложение из корня при сборке — отдельной копии кода нет; версия из `VERSION`. Подпись — из секретов (`android-app/make_keystore.py`), ключи не коммитить. Собирается и проверяется в эмуляторе только в GitHub Actions (`build-apk.yaml`, `android-app/ci/smoke.sh`): локально Maven/Google недоступны. Перезагрузка эмулятора в `smoke.sh` ограничена по времени (эмулятор GitHub изредка не возвращается): сбой эмулятора = «НЕ ПРОВЕРЕНО», не провал; настоящий провал приложения по-прежнему валит сборку.
- `transfer.py` — перенос данных между устройствами (ПК ↔ телефон): манифест файлов, «только новое» (материалы — по файлам, остальное — по категориям, «новее побеждает»), раздача по Wi-Fi (`Sender`: только частные IP, код 8 символов, 15 минут, блок после 10 ошибок) и приём (`pull`), архив `.zip` (`export_archive`/`import_archive`, защита от zip-slip), очистка настроек от секретов (`safe_settings`); пароль, cookies, токены и `notify.bin` не переносятся; без Moodle-кода и сторонних библиотек. Окно — `#trModal` в `ui/index.html`, API `/api/transfer*` в `gui.py`.
- `qr.py` — свой кодировщик QR (SVG) для окна переноса; без сторонних библиотек.
- `datadir.py` — где лежат данные (`.moodle_offline`): у .exe — папка пользователя (`%LOCALAPPDATA%\MoodleOffline`), `portable.txt` — рядом с exe; поиск и копирование данных прошлой версии при первом запуске (`prepare_data_dir`); без сторонних библиотек.
- `dl_rules.py` — правила скачивания (что брать, что пропускать) и шаблоны имён папок/файлов (режим 3); без сторонних библиотек.
- `cdp.py` — свой минимальный клиент DevTools Protocol для фонового Edge/Chrome (без сторонних библиотек).
- `schedule.py` обновляет сохранённую страницу сам: `refresh_viewer` (отпечаток `<!--viewer:…-->` в начале `Расписание/index.html`) пересобирает её из `schedule.json`, если просмотрщик новее.
- `tests/` — проверки (`python tests/run_all.py`; подробности — `tests/README.md`): `test_*.py` на макетах `mock_moodle.py` / `mock_iot.py` (без настоящих сайтов), `_root.py` (первая строка любого теста — `import _root`). В Actions — задача `tests` (`.github/workflows/tests.yaml`, Python 3.11 и 3.13, отдельно от сборок apk/exe: красный тест их не останавливает). Проверка поиска (`test_search_unit.py`) в Actions пропускается (нет LibreOffice) — гонять у себя. Окно в браузере (Playwright) и живая загрузка в репозиторий пока не перенесены. Личное в тесты не класть: имена, логины, `sesskey` — вымышленные.
- `*.bat`, `run.sh` — запуск и сборка. `.github/workflows/build-exe.yaml` — сборка exe в GitHub Actions: вручную (артефакт) или по тегу `v*` (ещё и выкладывает exe в Releases). `.github/workflows/build-apk.yaml` — то же для `MoodleOffline.apk` + проверка в эмуляторе Android.

## Правила
- Отвечать и писать комментарии/README по-русски. Объяснения короткие, простым языком.
- Вежливость к серверу: последовательные запросы, паузы, повторы с нарастающей задержкой, докачка. Не добавлять параллельную загрузку.
- Секреты не коммитить и не логировать: пароль, куки (`MoodleSession`, SSO), токен Telegram-бота и адрес webhook (`notify.bin`), содержимое `.moodle_offline/`, диагностические файлы с реальных страниц. Пароль вводится только на своём сайте (`sevsu.ru`, https).
- Сторонние библиотеки добавлять только при необходимости (список — `requirements.txt`).
- Перед PR прогони `python tests/run_all.py` (и на Python 3.11, и на 3.13); нашёл ошибку — сначала тест, который её ловит, потом исправление.
- Менял поведение — обнови `README.md`; выпускаешь версию — поменяй `VERSION` в `moodle_offline.py` (сборка по тегу `v*` сама ставит в файл версию из тега; тег ставят на коммит в `main`, и PR всегда открывать в `main`, а не в чужую ветку).
- Реальные сайты СевГУ требуют входа, поэтому автоматически их не проверить: проверяй на моках и честно пиши, что проверено, а что нет.
